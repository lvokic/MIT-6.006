# 为什么自底向上建堆是 O(n)

对应代码：[binary_heap.cpp](binary_heap.cpp)。这里用最大堆说明；最小堆的分析相同。

## 算法

把 n 个元素放入数组，按数组位置看成一棵完全二叉树。从最后一个非叶子节点开始，依次向前对每个节点执行 `sift_down`。

处理一个节点时，它的左右子树已经处理过并且是堆；`sift_down` 把当前元素沿一条向下的路径调整到合适位置。叶节点本身已经是堆，不需要调整。

## 为什么不能直接说 n 个节点、每个 O(log n)

这样乘出来的 `O(n log n)` 确实是上界，但太宽松：不是每个节点都有 `log n` 层可以下沉。大部分节点距离叶子很近。

对于满二叉树，可以先直观地这样计数：

```text
约 n/2  个节点是叶子：    最多下沉 0 层
约 n/4  个节点距底部 1 层：最多下沉 1 层
约 n/8  个节点距底部 2 层：最多下沉 2 层
约 n/16 个节点距底部 3 层：最多下沉 3 层
...
```

因此向下移动的总次数被以下数量级控制：

```text
(n/4) × 1 + (n/8) × 2 + (n/16) × 3 + ...
= n × (1/4 + 2/8 + 3/16 + ...)
```

括号中的无穷和等于 1，是不随 n 增长的常数；实际树只有有限层。因此这部分工作为 `O(n)`。每次 `sift_down` 的额外判断，以及扫描非叶子节点的开销也至多是 `O(n)`。

## 括号里的和为什么是常数

把每一项拆开，再按“第几份”分组：

```text
1/4 + 2/8 + 3/16 + 4/32 + ...

第一份：1/4 + 1/8 + 1/16 + ... = 1/2
第二份：      1/8 + 1/16 + ... = 1/4
第三份：            1/16 + ... = 1/8
...

合计：1/2 + 1/4 + 1/8 + ... = 1
```

## 更适用于不满最后一层的计数方法

也可以直接按每次下沉跨过的层数计数。一个节点最多下沉多少层，取决于它距离最深后代有多远。对完全二叉树：

```text
可能下沉至少 1 层的节点数 <= n/2
可能下沉至少 2 层的节点数 <= n/4
可能下沉至少 3 层的节点数 <= n/8
...
```

每个下沉 h 层的节点，在上面前 h 项中各计入一次，因此所有节点下沉层数之和不超过：

```text
n/2 + n/4 + n/8 + ... < n
```

每层只需常数次比较和交换，连同扫描节点的成本，建堆总时间为 `O(n)`。这个计数适用于最后一层未满的完全二叉树。

## 不要与逐个插入混淆

| 方法 | 操作 | 最坏总时间 |
| --- | --- | --- |
| 自底向上建堆 | 已有全部元素；从后往前对非叶子节点 `sift_down` | `O(n)` |
| 逐个插入建堆 | 从空堆开始；每插入一个元素后 `sift_up` | `O(n log n)` |

查看最大值 `peek` 是 `O(1)`；删除最大值 `delete_max` 需要将末尾元素移到根并 `sift_down`，最坏是 `O(log n)`。

## 应用：Fick Nury 4-2(a)

将 n 条调查记录复制到数组，自底向上建最大堆 `O(n)`；然后取出 `log n` 次最大值，花 `O(log² n)`。因此总时间是 `O(n + log² n) = O(n)`，额外空间是 `O(n)`。

注意使用大写 `O(n)`：它表示线性上界，不等同于小写 `o(n)`。
