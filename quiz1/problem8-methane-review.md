# Quiz 1 Problem 8–9：数据结构复习笔记

题目见 [Quiz 1 题目](originals/quiz1-questions.pdf)，官方答案见 [Quiz 1 解答](solutions/quiz1-solutions.pdf)。

## 题目要做什么

每个孔洞用 `(pipe_id, distance)` 表示。初始化时每根管道有一个孔；之后可以报告新孔洞。修补时：

- 如果所有管道都最多有一个孔，可以修补任意一个孔。
- 否则，找出同一管道内距离最小的一对孔，修补其中任意一个。

要求初始化 `O(n)`；报告和修补在当前有 `k` 个未修补孔洞时为 `O(log k)`。题目要求说明复杂度是最坏、期望还是均摊。

## 我提出的思路

1. 按管道组织孔洞；每根管道用一棵按 `distance` 排序的 AVL 树。
2. 插入新孔时，只需要检查它的前驱和后继与它的距离，来判断是否出现新的最小间距。
3. 使用全局堆管理每根管道的最小间距，维护 `pipe_id -> 堆中位置`，堆节点交换时更新位置。
4. 原先考虑额外维护按孔洞数量排序的堆，用它判断是否存在有多个孔的管道。
5. 原先考虑保存 `pre_minimum`，在删除当前最小间距对应的孔洞后恢复上一次的最小值。

第 2 点对于**插入**是正确的：新出现的最小间距只可能是新孔与前驱或后继的间距。对于删除，仅保存一个 `pre_minimum` 不够，因为删除会同时移除两个相邻间距，还可能产生一个新的间距。

例如：

```text
孔洞位置： [0, 1, 3, 6, 10]
相邻间距： [1, 2, 3, 4]

删除位置 1 后：
孔洞位置： [0, 3, 6, 10]
相邻间距： [3, 3, 4]
```

旧的间距 1 和 2 均消失，出现新的间距 3；不能只恢复一个历史最小值。

## 最终方案

### 每根管道：增广 AVL 树

按 `distance` 存储孔洞。在每个节点额外维护：

- `min_distance`：子树中最小的孔洞位置。
- `max_distance`：子树中最大的孔洞位置。
- `min_gap`：子树中相邻孔洞的最小间距；少于两个孔洞时为正无穷。
- 一对产生 `min_gap` 的孔洞位置或节点引用，便于 `patch()` 找到要删除的孔。

对于节点位置 `d`，其 `min_gap` 从以下候选中选最小值：左子树的 `min_gap`、右子树的 `min_gap`、`d - 左子树的 max_distance`、`右子树的 min_distance - d`。不存在的子树不参与比较；同时记录取得最小值的那一对孔洞。

这些信息可以根据节点及两个孩子在 `O(1)` 时间计算。插入、删除和旋转时，沿受影响路径更新；旋转后先更新较低节点，再更新新的子树根。每棵 AVL 的根即给出对应管道的最近孔洞对。

为什么只需要相邻孔洞？如果两个非相邻孔洞之间还有一个孔，其中至少有一段相邻间距更小，因此全局最小间距可以由一对相邻孔洞取得。

### 全局：按每根管道的最小间距维护堆

维护一个最小堆，每个**非空管道**有一个堆条目，key 是该管道 AVL 根的 `min_gap`：

- 两个或更多孔：key 为有限的最小间距。
- 恰好一个孔：key 为正无穷。
- 没有孔：不保留堆条目。

若堆顶 key 有限，它就指向全局最近的一对孔。若堆顶为正无穷，则所有非空管道都只有一个孔，可以修补堆顶管道的唯一孔；堆为空则无孔可修补。因此不需要额外按孔洞数量维护一个堆。

使用字典 `pipe_id -> 管道记录`，管道记录保存 AVL 根和当前堆下标。堆条目持有指向记录的引用，交换堆元素时直接更新两条记录中的下标；避免在每次交换时再通过平衡树查找而增加复杂度。

## 操作与复杂度

下面采用随机哈希表作管道字典、动态数组实现堆；假设哈希表的扩缩容与随机哈希具有通常的均摊期望保证。`k` 很小时可把对数写成 `log(k + 1)`。

| 操作 | 过程 | 时间 |
| --- | --- | --- |
| `initialize(H)` | 为每根管道建立含一个孔的记录与堆条目；一次性自底向上建堆 | `O(n)` 均摊期望；建堆本身最坏 `O(n)` |
| `report(p, d)` | 查找或创建管道；将孔插入对应 AVL，更新增广信息和该管道的堆 key；如果是新非空管道则添加堆条目 | 均摊期望 `O(log(k + 1))` |
| `patch()` | 查看堆顶，按规则选孔；从对应 AVL 删除并更新堆 key；若管道变空则移除堆及字典条目 | 均摊期望 `O(log(k + 1))` |

AVL 查找、插入、删除及树上增广更新本身为最坏 `O(log(k + 1))`；哈希字典引入期望复杂度，动态扩容可能引入均摊成本。维护或删除条目时，更新堆位置引用；若实现 AVL 删除时会搬动或销毁节点，必须保证所保存的最近孔洞引用同步有效。

初始化时每根管道已有一个孔，所以逐管道建单节点 AVL 和建立 `n` 个堆条目，再用线性时间建堆即可；不要逐个堆插入后直接声称最坏 `O(n)`。

## Problem 8：这次需要巩固的地方

- 最初已经想到“每根管道用 AVL、全局用堆、用索引定位堆条目”的整体分工。需要补充的是：**删除会改变哪些信息**，以及已有信息是否足够计算新答案。
- 插入时只检查新节点的前驱和后继，这是因为只有新产生的相邻关系可能创造更小间距；删除时，两条旧间距可能消失、一条新间距可能出现，不能依靠一个历史 `pre_minimum` 恢复答案。
- 设计增广信息时，检查能否从当前节点和两个孩子在 `O(1)` 时间算出信息，并说明旋转、删除时如何更新。
- 根据题目优先规则检查冗余结构：单孔管道使用无穷大的间距后，全局堆也能表示“每管最多一孔”，不必额外按孔数建一个堆。

## Problem 9：Vapor Invite

### 题目要做什么

用户有唯一的正整数 ID，状态可在活跃和不活跃之间切换。一个闭区间 `(a, b)` 合法，当且仅当所有 ID 落在区间中的用户都活跃。返回包含最多活跃用户的合法区间。

要求：`build` 最坏 `O(n log n)`、切换状态最坏 `O(log n)`、查询最大活跃区间最坏 `O(1)`。

### 我提出的思路

- 按用户 ID 建立 AVL 树；每个节点维护子树中最大的活跃区间，状态变化后向上更新到根，查询时直接读取根节点。
- 考虑把活跃与不活跃用户分别放在两棵 AVL 树中：不活跃用户充当分隔点，切换时拆分或合并区间。

这两种方向都可以继续发展；根节点缓存全局答案、向上只更新一条路径是关键。需要补足的是：节点到底保存哪些信息，才能在状态变化后于 `O(1)` 时间由两个孩子更新自己。

### 需要纠正和补充的地方

1. **仅保存子树的最大活跃区间不够**。跨越父节点的答案，可能来自左子树末尾的活跃段、父节点和右子树开头的活跃段；左／右子树各自内部的最大段不一定贴近边界，不能直接拼接。
2. 可以为每个子树维护按 ID 顺序的 `prefix`（最左端开始的连续活跃段）、`suffix`（到最右端结束的连续活跃段）、`best`（内部最长活跃段），以及子树大小或是否全部活跃。还要保存需要返回的端点。每个节点利用两个孩子及自身状态，在 `O(1)` 时间合并这些信息。
3. 所谓连续，是**用户按 ID 排序后连续活跃**，不是要求 ID 数字相邻。例如用户 ID 为 `2, 7, 20`，三人均活跃时 `(2, 20)` 是合法区间；区间内不存在用户的整数 ID 不构成障碍。
4. 原题是闭区间：如果 ID 为 `c` 的用户不活跃，`(a, c)` 和 `(c, b)` 都包含 `c`，不能直接作为合法活跃区间。可以保存实际活跃用户的首尾 ID 来表示答案。
5. 即使被切换的用户在当前全局最佳区间之外，也不能跳过祖先信息更新：其他区间可能因此变成新的最佳区间，或者影响后续切换。只维护全局最佳值而不维护其他候选信息不够。
6. 用户集合固定时，用一棵按 ID 排序的树，切换节点的状态即可，不必结构性插入或删除。两棵树方案也可行，但仍需用不活跃用户的位置作为分隔，并额外维护各区间人数和全局最大者，才能 `O(1)` 返回答案。

构建平衡树并初始化增广信息可在最坏 `O(n log n)` 内完成；切换后沿根路径更新最坏 `O(log n)`；查询读根节点保存的答案是 `O(1)`。如果所有用户不活跃，需要约定返回一个不包含任何用户的合法区间或按题意说明这一边界情况。
