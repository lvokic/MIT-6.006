## Problem 3-1：Hash It Out

**题意**：依次将 `[67, 13, 49, 24, 40, 33, 58]` 插入大小为 9 的哈希表，哈希函数是 `h(k) = (11k + 4) mod 9`。冲突使用 chaining，新元素放在链表末尾，画出最终哈希表。

本次对话没有记录这题的具体计算过程；复习时可按插入顺序重新计算各个桶，并检查冲突链的顺序。

## Problem 3-2：Hash Sequence

**题意**：把哈希表当作黑盒，仅通过它的 Set 接口实现 Sequence。要求 `build` 期望 `O(n)`，`get_at` / `set_at` 期望 `O(1)`，中间插入 / 删除期望 `O(n)`，首尾四种动态操作均摊期望 `O(1)`。

### 自己提出的方案：deque + hash map

- `deque` 按序列顺序存整数 key：下标代表序列位置，元素是对应的 key。
- 哈希表存 `key -> value`。每次插入分配一个尚未使用的 key；value 可以重复。
- `get_at(i)` 通过 `deque[i]` 得到 key，再通过哈希表查找；`set_at(i, x)` 同理。
- 首尾插入和删除同时更新 deque 和哈希表；中间插入和删除允许移动 `O(n)` 个 key。
- 需要确认课程是否允许使用 deque 作为额外辅助结构，以及 key 分配方式的成本和整数范围；哈希表本身仍只通过 Set 接口访问。

曾考虑用 `value -> 双向链表节点`：它便于首尾操作，但无法根据下标直接取得第 `i` 个节点，且重复 value 不能作为唯一 key。

### 讨论补充：官方的 start 偏移方案

哈希表存 `key -> value`，维护起始 key `start` 和长度；位置 `i` 映射到 key `start + i`。在首部插入时，将新元素放在 key `start - 1`，再把 `start` 减 1，不需要重编号现有元素。末尾操作同理；中间操作可逐个移动受影响的 key。

`find(key)` 是 Set 的按 key 查找；`get_at(i)` 是 Sequence 的按位置访问，后者通过 `find(start + i)` 实现。哈希表偶尔扩容可花 `O(n)`，但若其扩缩容策略有相应保证，首尾操作仍可达到均摊期望 `O(1)`。

## Problem 3-3：Critter sort

**题意**：分别按物种 ID、名字、战斗次数、胜率，对 `n` 只 Critter 排序。题目说明越快的正确算法得分越高。

### (a) 物种 ID：`-n <= xi <= n`

**自己提出**：计算 `xi + n` 后排序；也考虑过 merge sort。

**讨论补充**：平移后 key 在 `0..2n`，用 counting sort / 桶可以做到最坏 `O(n)`；merge sort 为 `O(n log n)`。`n` 是输入规模，不是固定常数，但桶数仍为 `O(n)`。保留完整 Critter，重复 ID 可以放在同一桶。

### (b) 名字：唯一字符串，长度最多 `10 × ceil(log₂ n)`

**自己提出**：按字典序比较，使用 merge sort。

**讨论补充**：逐字符比较一次最坏 `O(log n)`，所以 merge sort 最坏 `O(n log² n)`。按字符做稳定 radix sort，使用小于所有字母的结束符处理不同长度，可做到 `O(n log n)`。官方还讨论了紧凑存储和机器字模型下的编码方案，可在线性时间排序；如果需要逐字符读取输入，输入本身可能有 `O(n log n)` 个字符。

### (c) 战斗次数：正整数 `fi < n²`

**自己提出**：使用基数 `n` 的 radix sort，把 `fi` 分为高位 `fi / n` 与低位 `fi % n`；每一位用 counting sort，可以用链表桶或前缀和 + scatter。

**讨论补充**：先低位后高位，各轮必须稳定。两轮各花 `O(n)`，总计最坏 `O(n)`。小规模边界可单独处理。

### (d) 胜率：`wi / fi`，`wi <= fi`

**自己提出**：数字范围小时考虑 radix sort + counting sort，否则用 merge sort。

**讨论补充**：merge sort 可用交叉相乘精确比较：`w1 * f2 < w2 * f1`，避免浮点误差，最坏 `O(n log n)`；实现时要考虑整数溢出。利用 `fi < n²`，不同胜率相差至少 `1/n⁴`，可构造 `floor(wi * n⁴ / fi)` 保持顺序，再做常数轮 radix sort。后者的 `O(n)` 分析依赖课程的机器字和整数运算模型；实际实现也要处理溢出。

## Problem 3-4：College Construction

**题意**：从给定正整数边长集合中选两个立方体，上下堆叠；高度上限是 `h`。(a) 判断能否恰好达到 `h`，要求期望 `O(n)`；(b) 已知不能恰好达到，且 `h = 600n⁶`，找不超过 `h` 的最大边长和，要求最坏 `O(n)`。

### (a) 精确和

**自己提出**：扫描边长，维护 `seen` 哈希表；对 `s` 查询 `h - s` 是否已出现，再将 `s` 加入。期望时间 `O(n)`。

**讨论补充**：先查再插默认要选两个不同的集合元素。若供应商允许购买两个相同边长，还需允许 `s + s = h`。使用哈希表而非通常 `O(log n)` 查找的 `std::map`。

### (b) 最接近但不超过上限

**自己提出**：把边长按基数 `n` 拆成数位，稳定 counting sort，可用前缀和 + scatter。位数不足时在高位补 0。

**讨论补充**：先过滤 `s >= h`，因为另一个边长为正，这些值不可能用于合法组合；否则截取固定数位可能丢失高位信息。过滤后 `s < 600n⁶`：低 6 位基数为 `n`，最高位范围为 `0..599`，因此是 7 位、7 轮稳定排序，最坏 `O(n)`；`n = 1` 可单独处理。

排序后还需用双指针找边长对：若两端之和不超过 `h`，更新最佳结果并移动左指针；否则移动右指针。此步最坏 `O(n)`。根据是否允许相同边长，选择 `left <= right` 或 `left < right`；还要处理不存在合法组合的情况。
