## Problem 1-2：Stone Searching

**题目（中文）**：星球编号为正整数，石头位于未知的星球 `k`。询问编号为 `x` 的星球上的 oracle，可以知道石头是否在编号严格大于 `x` 的星球上。设计一个算法，在最多 `O(log k)` 次询问内找到 `k`。

### 思路

普通二分搜索需要一个有限的上界，而这里开始时不知道 `k` 的上界。先询问 `1, 2, 4, 8, ...`，直到第一次得到“石头不在更高编号的星球上”。若该编号为 `2^m`，则 `k <= 2^m`；若 `m > 0`，上一次回答还表明 `k > 2^(m-1)`。再在这个有限区间内二分。

- 每次询问中点 `mid`：如果石头在更高编号，搜索 `mid + 1` 及以后的部分；否则保留 `mid` 及其左边。
- 倍增和二分各需要 `O(log k + 1)` 次询问，总计 `O(log k + 1)`；题目通常简写为 `O(log k)`。
- **复习重点**：未知上界时，先用倍增建立范围，再二分。注意 `k = 1` 和 oracle 回答中的“严格大于”。

## Problem 1-3：Collage Collating

**题目（中文）**：维护一个图片文档，每张图片有唯一整数 ID。支持：

1. `make_document()`：创建空文档，最坏 `O(1)`。
2. `import_image(x)`：将图片 `x` 加到最上层，最坏 `O(n)`。
3. `display()`：返回从下到上的图片 ID 数组，最坏 `O(n)`。
4. `move_below(x, y)`：将图片 `x` 移到图片 `y` 的正下方，最坏 `O(log n)`。

其中 `n` 是操作时文档中的图片数。

### 讨论出的方案

用**双向链表**维护从下到上的图层顺序；用平衡搜索树维护 `ID -> 链表节点`，例如 C++ 的 `std::map<int, Node*>`。

| 操作 | 做法 | 最坏时间 |
| --- | --- | --- |
| 创建 | 创建空链表和空 map | `O(1)` |
| 导入 | 链表顶部插入节点，并将 ID 和节点指针加入 map | `O(log n)`，满足题目 `O(n)` 上界 |
| 展示 | 从底到顶遍历链表，写入数组 | `O(n)` |
| 移动 | 用 map 找到两个节点；摘下 `x`，插入 `y` 的前面 | `O(log n)` |

链表已知节点后的摘除和插入都是 `O(1)`。移动节点不改变节点身份，因此 map 中的指针仍然有效。处理 `x == y`，以及头尾插入等边界情况；哨兵节点可以简化指针操作。

**复习重点**：链表维护图层顺序，map 按 ID 查找，它们各自解决不同问题。`std::map` 和 `std::set` 通常用红黑树实现，标准不规定必须采用红黑树；`set<int>` 按 ID 排序，不能直接表示任意图层顺序。

动态数组在末尾追加通常是 `O(1)`，扩容复制时单次可能是 `O(n)`；按比例扩容时追加均摊 `O(1)`。如果顶层定义在数组开头，插入可能每次都要移动 `O(n)` 个元素。

## Problem 1-4：Brick Blowing

**题目（中文）**：房子从西到东排列，数组 `H` 存放每栋房子的砖块数。狼对编号为 `i` 的房子向东吹时，这栋房子倒塌，东边所有砖块数**严格小于** `H[i]` 的房子也倒塌；中间出现更坚固的房子不会阻止风继续影响更东边的房子。每栋房子的 damage 是这样倒塌的房子总数。

- **(a)** 对 `[34, 57, 70, 19, 48, 2, 94, 7, 63, 75]` 求每栋房子的 damage。
- **(b)** 若一栋房子没有东边紧邻房子，或者其东边紧邻房子的砖块数至少与它相同，则称其为特殊房子。假设恰好只有一栋房子不特殊，设计 `O(n)` 算法求所有 damage。
- **(c)** 对一般数组设计 `O(n log n)` 算法。
- **(d)** 用 Python 实现 `get_damages(H)`。

### (a)：如何理解题意

所有房子都需要计算 damage，不仅是砖块数创下新高的房子。例如对砖块数为 19 的房子吹，其东边的 2 和 7 都会倒，加上自己，damage 为 3。明天可独立算出完整数组再验证。

### (b)：唯一下降点与双指针

最东边房子因为没有东边邻居，按定义是特殊的；它不需要满足两个条件。设唯一不特殊的房子下标为 `p`，则 `H[p] > H[p+1]`，且两段 `H[0..p]`、`H[p+1..n-1]` 各自非递减。

- 右半段的每栋房子，东边都没有严格更弱的房子，damage 均为 1。
- 左半段的一栋房子，左半段内部位于其东边的房子不会倒；只需统计右半段中严格比它小的房子。
- 依次扫描左半段，用指针 `j` 在右半段向右移动到第一个不小于 `H[i]` 的位置：`damage[i] = 1 + j - (p + 1)`。右半段已经包含最后一栋，不需额外统计。
- 两段各自非递减，所以指针无需回退；寻找 `p` 和双指针扫描总计 `O(n)`。

### (c)：归并排序统计每个位置的逆序对

对每个 `i`，要计算 `1 +` 满足 `j > i` 且 `H[j] < H[i]` 的 `j` 的数量。

1. 按原始位置将街道递归分成左右两半。分别解决两半内部的 damage。
2. 递归返回时，两半各按砖块数排序，同时保留每栋房子的原始下标。
3. 归并时，左半边每栋房子原本都在右半边所有房子的西边。维护 `smaller`：已归并的、严格小于当前左侧房子的右侧元素个数。放入左侧房子时，将 `smaller` 加到其 damage。
4. 砖块数相等时先放左侧房子，确保相等的右侧房子不会计入。

每对房子恰好在它们首次分到左右两半后的那次归并中被考虑；左右半边内部的关系已经在递归中处理。每层总工作 `O(n)`，共 `O(log n)` 层，因此 `O(n log n)`。

**从 (b) 到 (c) 的联系**：两段有序时可用双指针；一般数组没有这种性质，于是用递归人为构造两个有序半段，并在归并时统计跨两段的贡献。

### 做题思维与踩过的坑

- 先把条件写成 `j > i` 且 `H[j] < H[i]`。尝试分别思考：先处理哪个条件，剩下的操作是什么？
- 按砖块数排序能找到更弱的房子，但还要快速统计它们中有多少位于东边。知道原始 index 不等于能高效计算排名；`std::map` / `std::set` 的 `lower_bound` 是 `O(log n)`，但用 `std::distance` 计算排名可能要 `O(n)`。`std::set` 还会去重。
- 按砖块数排序的路线也可行，例如用树状数组统计原始下标范围内的数量；相同砖块数要分组处理，避免互相计入。反复从 vector 中 `erase` 中间元素可能达到 `O(n²)`。
- 归并排序先用位置拆分，让“右半边在东边”自动成立；再利用排序统计砖块大小条件。
